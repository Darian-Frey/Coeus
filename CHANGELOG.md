# Changelog

Format follows [Keep a Changelog](https://keepachangelog.com).

## [Unreleased]
### Fixed
- BUG-008: in a vault that is a Git repository, the embeddings sidecar counted as a changed file and appeared in every commit dialog; `.coeus-shared/` is now one of Coeus's own files, like `.coeus/`.

### Added
- Embeddings sidecar (F-035): `.coeus-shared/embeddings.bin` carries passage vectors between machines by hash (D-011), so a second machine embeds only what changed. The embedding worker imports from it before embedding anything and rewrites it, atomically and as a union, when a pass ends with something new; `coeus --mcp` does the same. Vectors of another model or dimension, or from a damaged file, are never imported (AV-007, AV-011). A sync tool's conflict copies are united and removed. File › Compact Embeddings Sidecar drops passages the vault no longer has, as does a weekly compaction (`[semantic] sidecar_compact_days`). Test `test_sidecar`.
- Related notes (F-019): a Related section in the sidebar lists the five notes nearest in meaning to the current note that it does not already link to, with the passage that matched; clicking opens it there and Link here inserts a wikilink at the cursor, written as the completer would. It is worked out off the UI thread from stored vectors, and again after saves and as embedding progresses. Each match is discounted by how typical the note's passage is across the vault, so scaffold boilerplate shared by every project no longer decides the list. MCP gains `related`. Tests: `test_semantic` (boilerplate case), `test_semantic_window`, `test_mcp_server`.
- Search by meaning (F-018 complete): notes are split into passages at index time (headings, and each register entry; index schema 5) and an embedding worker gives each distinct passage a vector in the background, with progress in the status bar. The search pane gains Words, Meaning and Both, which merges the two rankings; MCP `search` gains `semantic` and `hybrid`, embedding what the window has not, within 2 s. Vectors live in a plain table scanned per query (D-008 amended), dropped when the model changes (AV-007). On the author's 3,661 passages a search takes about 55 ms. Tests `test_semantic`, `test_semantic_window`; `test_mcp_server` gains meaning.
- Embedding model for semantic search (D-008 accepted, F-018 step 1): bge-small-en-v1.5 runs on the CPU inside Coeus through llama.cpp, built from source at the pinned release b10926; `tools/fetch_model.py` downloads the 67 MB model once per machine and verifies its SHA-256, so it never enters the repository. `search/Embedder` makes unit vectors, with bge's query prefix for searches. Tests `test_embedder` (skipped without the model), `test_fetch_model`.
- MCP write tools (F-033 complete): `next_id`, `append_entry` and `write_note`, refused until `[mcp] allow_writes = true`. `append_entry` writes an entry to the standard with the next free ID, refusing vocabulary errors and missing required fields before reserving anything, and places BUG and IMP entries in their status section. `write_note` creates, replaces or appends to notes but never registers. With the window open, notes with unsaved changes are refused and each write shows a toast with a 10 s Undo, over a per-user local socket. Tests `test_entry_writer`, `test_mcp_window` (the real server beside a window); `test_mcp_server` gains the write tools.
- MCP server, step 1 (F-033): `coeus --mcp --vault <folder>` serves the vault's index over stdio to Claude Code, Claude Desktop or any MCP client, without a display or the GUI. Read tools `search`, `get_note`, `list_registers`, `project_status` and `list_ideas`; the index is brought up to date before each call. Root reconciliation moved into `index/IndexRoots` and the board's per-project reading into `registers/ProjectOverview`, so the GUI and the server share them. BUILD.md shows how to register it with Claude Code, the client it is built for, and optionally LM Studio (D-021). Test `test_mcp_server`, which also drives the binary over stdio.
- Project board commands (F-032 complete): Refresh Header… sets a README's Last reviewed to today after confirmation (in the open buffer if it is open); Promote Idea… turns an idea into a project in `projects/<codename>/` or a new folder added as a linked root, with the status header and the standard's skeletons and no IDs, removing the idea note once everything is written; Fetch runs `git fetch` in each project's repository (D-020 amended). `GitPush` became `GitCommand`. Tests `test_board_commands` (including a fetch that finds another clone's push), and cases in `test_project_status` and `test_roots`.
- Project board (F-032, step 1): a Project Board dock (`Ctrl+Shift+J`) lists every project by README status, with days since Last reviewed (amber past the threshold), build status from ROADMAP.md, unreleased CHANGELOG entries, and Git branch, ahead/behind and changed files; then ideas by stage. Notes under `ideas/` with a `stage` are indexed (schema 4). Read on the Git worker. Tests `test_project_status`, `test_project_board`; `test_git_commit` gains ahead/behind.
- Commit from Coeus (F-022): the status bar counts the current repository's changed files (Coeus's own files never included); Git › Commit… (`Ctrl+Alt+C`) or the count opens a dialog listing them with ticks (tracked changes and notes ticked), unsaved open notes with Save All, a multi-paragraph message and Push after committing. libgit2 commits exactly the ticked paths, leaving anything else staged as it was; push runs `git push` in the background with prompts off (D-020), its result in the status bar. Tests `test_git_commit` (including a real push to a bare remote), `test_commit_dialog`.
- Diff and blame (F-021): Git › Diff with HEAD (`Ctrl+Alt+D`) and History's Diff vs HEAD compare the live buffer with HEAD; a commit's menu compares it with the version before or the working copy, and two selected commits with each other. Each opens a read-only tab with the whole note, removed and added lines marked, line numbers and change navigation. Git › Toggle Blame (`Ctrl+Alt+B`) and History's Blame open a gutter naming each run's commit and date, blaming the buffer (unsaved lines *Not committed*) and again after typing pauses. History keeps its note and selection while that note's version or diff tab is current. Test `test_diff_blame`; `test_git_repository` gains blame and diff.
- Per-note Git history (F-020): a History section in the sidebar lists the current note's commits through libgit2 (`git/GitRepository`), following renames and skipping merges that took one side unchanged, with the branch; clicking one opens that version read-only in its own tab. libgit2 runs on a one-thread Git worker. The demo's Pontus root gains two commits. Tests `test_git_repository`, `test_history_panel`; history matches `git log --follow` on Coeus and Pontus (69 commits in 25 ms).
- `coeus --lint [--strict] [--quiet] [--mentions] <folder>` (IMP-004): the register lint from a terminal, without a display, into a temporary index; `--mentions` also reports IDs mentioned in a project's notes that it does not define. The pre-commit hook and the new `lint_coeus_docs` ctest entry use it. Test `test_lint_command`.
- Register validation (F-016): lint rules L1–L9 (unresolved, stale and one-way citations, vocabulary, required fields, stale review, duplicate IDs) run after every index change and are stored in index schema 3; L8 is evaluated when read. A Problems dock (`Ctrl+Shift+M`) lists them by file for the current project or all, filtered by level; the status bar counts the current project's; the editor underlines each with a wavy line and shows it on hover. Vocabulary terms may carry qualifiers (`fixed (2026-10-05)`). L4 follows the standard's back-reference pairs over mentions anywhere in an entry and matches `tools/check_xrefs.py` on Coeus. Fixed BUG-006 (hyphenated field names such as `Trade-offs`) and BUG-007 (a root whose own README is a project failed to index). Tests `test_lint`, `test_problems_panel`. Across `~/Projects`: 381 problems in 12 ms.
- Registers, step 2 (F-015, F-010 complete): a Registers dock lists a project's entries with kind, status and text filters, following the current note and opening entries at their line; typing `D-` (or any kind) completes the project's IDs; Insert Next ID… (`Ctrl+Shift+I`) allocates through `NextId` (`BEGIN IMMEDIATE`, register files read from disk, unsaved buffer and 60 s reservations counted), creates a missing register file from its skeleton and appends the entry with its title selected; `{{next:KIND}}` in templates takes a real ID. The command palette can keep its given order. Tests `test_next_id` (including eight concurrent allocators) and `test_register_commands`.
- Registers, step 1 (F-015): `RegisterParser` reads entries, fields, citations and README status headers; `ProjectResolver` derives projects, nested membership and citation targets after every index change. Index schema 2 (`status_headers`, `registers`, `register_fields`, `register_refs`, `lint`, `reservations`); older indexes rebuild. Tests `test_register_parser`, `test_projects`; rebuild equivalence now covers projects and registers. Across `~/Projects`: 9 projects, 508 entries.
- Daily notes (F-009): `Ctrl+D` opens or creates today's note at `[daily] folder/format`, optionally from `[daily] template`, never overwriting. Templates (F-010): Insert Template… renders `{{date}}`, `{{time}}`, `{{title}}` and formatted variants into the buffer, merging frontmatter keys the note lacks. The demo vault gains templates and a daily template. Tests `test_daily_templates`, `test_daily_template_commands`.

Tests `test_frontmatter_edit`, `test_properties_panel`.

### Fixed
- Tool strip buttons without an icon in the desktop's theme (Toggle Tags and Toggle Sidebar on Linux Mint) showed their names; Coeus now ships its own icons as a fallback (`ui/Icons`, `resources/icons/`), so every button has one on any machine. Test `test_main_window`.

### Changed
- `registers` drops SPEC's `UNIQUE(project_id, kind, number)` and allows a NULL project, so duplicate IDs are indexed for lint to report (AV-003) instead of failing silently.
- The sidebar's Properties placeholder is gone: properties sit above the note, as F-008 and the mockup place them.
- D-014 amended: reading mode uses `HtmlRenderer`, not md4c-html, which is no longer a dependency. The attachment-extension rule moves into `parser/` so the parser does not depend on `index/`.
- SPEC §Autosave journal: journal entries older than their note are offered too, flagged, rather than hidden; new §Editing.
- libgit2 is now a build dependency (for `.gitignore` rules), ahead of Phase 3's Git features.
- SPEC §Linked roots gains name, path, id, absent-root, removed-root and ignore rules; new §File watching.
- SPEC §Index schema: `links.ambiguous`; no migrations, a mismatched or unreadable index is rebuilt; indexed-file rules; resolution recomputed per update; file links (attachments, Markdown links to non-`.md` files) are neither resolved nor counted as broken.
- SPEC §Markdown dialect: local Markdown links are links, resolved relative to the note's folder; all-digit tags excluded and tag letters may be any script, as in Obsidian; embeds found by `parser/`; frontmatter property type inference. `links` gains `style`, `props` gains `line`.
- ROADMAP Phase 2 deliverables now cover every Phase 2 feature's acceptance: `AtomicWriter`, rebuild-equivalence check, `.gitignore` offer, autosave journal, conflict prompt, reading mode, unlinked mentions.
- Phase 1 (GUI shell) Complete; F-001 and F-002 Complete (2026-10-12).
- Minimum Qt lowered from 6.5 to 6.4 to build against the distribution's packaged Qt (Mint 22, Ubuntu 24.04).
- C++20 → C++23 so `std::expected` is available (BUG-001, D-013).
- `fts` stores its own text so snippets work (BUG-002).
- `.coeus/` in `.gitignore` is offered on first open, not written unasked (BUG-003).
- CLAUDE.md and ROADMAP Phase 1 aligned with F-001/F-002: command palette, attachments in the explorer (BUG-005).
- SPEC §Vault layout shows `ideas/`, `.coeus/journal/`, `.coeus-shared/`.
- F-017 review-freshness dashboard withdrawn, absorbed into F-032.
- ROADMAP Phase 2 gains F-034; Phase 3 gains F-032, F-033, F-035; Phase 5 acceptance covers two-machine convergence.
